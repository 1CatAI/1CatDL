# 已有实例更改 GPU 配置

客户在“我的实例”点击“更改配置”，仅可对状态为 `stopped`、无待处理动作且已释放 GPU/SSH 端点的自有实例操作。可选 1 或 4 卡；八卡实例只允许降级，任何已有 1/4 卡实例都不能改成八卡。切换 GPU 数量不热改正在运行的虚拟机。

`POST /api/rental/instances/{id}/gpu-plan`，登录客户提交 `{"gpuCount": 1}` 或 `{"gpuCount": 4}`。后台在单个 SQLite 事务里验证归属和运行状态，更新下次 GPU 启动的固定 CPU/内存规格、清除单卡人工内存覆盖、记录审计，并刷新 48 小时闲置计时。请求不预占显卡；下次开机在实例原所属节点重新检查卡组、CPU/内存和镜像状态。GPU 运行费率由届时选定套餐决定，无头模式仍固定 2 vCPU/4 GB 和原无头费率。

八卡实例的 600 GiB 数据盘继续挂在原节点的原实例磁盘路径。数据库 `eight_card_gift_disk` 标识八卡赠盘来源，迁移时为既有八卡记录回填；降级时标识、`gift_data_disk_gib=600`、`data_disk=0` 均不变。控制器给节点代理的保留盘标记只用于降级后的 1/4 卡规格，代理仅接受标记为真的 600 GiB 磁盘；未标记的 1/4 卡仍受原 200 GiB 上限约束。磁盘不缩容、不重建、不转为收费容量。其他管理员手动赠盘的旧行为保持不变。

发布顺序：先备份代码、数据库与节点代理；确认两节点均换成识别保留盘标记的代理，再开放控制器接口和新 UI。升级前后的客户 VM 不需因换配功能停机；控制服务重启可能导致 SSH 短暂断线。已有八卡降级实例时不得只回退到不认识保留盘标记的旧代理/控制器，也不得恢复旧数据库覆盖账单；如需回退，仅回退 UI 或先完成带数据保护的前向修复。

隔离测试：`python -m unittest -v test_gpu_plan_change test_eight_gpu test_gpu_plans test_server_http`。特别检查：运行/回收中拒绝、跨租户拒绝、8→4→1 后不能升八、赠盘物理容量和零存储计费、远端代理对有/无标记载荷的区别，以及下次开机的卡组容量门禁。
